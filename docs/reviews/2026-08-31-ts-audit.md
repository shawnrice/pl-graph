## 1. Systemic: prototype-chain lookups (`key in obj`, `obj[userKey]`) — THE headline

A plain object (`{}`) inherits `toString`/`constructor`/`hasOwnProperty`/`valueOf`/…
from `Object.prototype`. `'toString' in {}` is `true` and `({})['toString']` is a
function — with **no** patching, triggered by ordinary user data (a property named
`toString`, a GQL fn `toString`, an MCP algo `constructor`). Two harms: (a) a
**byte-identity break** vs the HashMap-backed Rust engine (which has no inherited
keys); (b) wrong values / mis-dispatch / rollback corruption. Fuzzers miss it (they
never generate reserved-word keys). Fix pattern already exists in-repo
(`executor.ts:284` `propPresent`, `projection.ts:380` `selectStep`, `protocol.ts` `Map`,
`temporal.ts:673`).

- [ ] **[high]** core `Vertex.ts:248` (+`121,158,159,222,230`), `Edge.ts:118` (+`141,176,177,232,240`) — `key in this.properties`: `hasProperty('toString')`→true → byte-identity break **and** rollback corruption (undo restores inherited fn) → `hasOwn`.
- [ ] **[low]** core `Graph.ts:2295,2405,2575,2907` — same in constraint checks (key is a declared-constraint name, lower risk) → `hasOwn`.
- [ ] **[high]** gremlin `dispatch.ts:183,407`; `projection.ts:170,195,261,287,314` — `has`/`values`/`valueMap`/`elementMap` emit inherited fns → `hasOwn` (sibling `selectStep:380` already does).
- [ ] **[med]** gremlin `misc.ts:88-93,225,232` — `math()` `UNARY_FN[name]`/`BINARY_FN[name]`/`MATH_CONSTS[name]` invoke prototype fns instead of faulting → `Object.create(null)`/`hasOwn`.
- [ ] **[high]** gql `scalars.ts:784` `NUM_CONSTANTS` + `759,765,771,713,725` (`UNARY_NUM`/`STR_ARG_POSITIONS`/…) — `RETURN toString(5)` leaks a raw `TypeError` `code:undefined` from the public API (violates LenkeError-code invariant) → build tables with `Object.create(null)`.
- [ ] **[med]** gql `clauses.ts:194` — `_MERGE` key inference `key in properties` on user map → `hasOwn`.
- [ ] **[high]** serialization `csv/index.ts:674` — `!(key in bag)` → encodes `"function Object()…"` for a missing cell → breaks round-trip + byte-identity → `hasOwn`.
- [ ] **[high]** mcp `tools.ts:198` — `ALGORITHMS[name]` invokes prototype fns (schema `enum` not enforced server-side) → `hasOwn` or make `ALGORITHMS` a `Map` (mirrors `protocol.ts`).
- [ ] **[med]** sync `engine.ts:333` — `scopeOf` `!(k in params)` mis-resolves scope to `Object` → `hasOwn`.
- [ ] **[med]** FUZZER GAP — differential/gremlin/codec/write fuzzers never generate reserved-word property keys (`constructor`/`toString`/`__proto__`/`hasOwnProperty`). Add them to the key generator so this class can't regress; re-run `bun run fuzz`.

> NOT bugs (correctly left alone by reviewers): `'from' in element`, `'label' in item`,
> `'hop' in el`, `'id' in v` (internal tagged-union discriminators), and
> `'size' in set` / `'length' in x` (testing an _inherited_ prop — `hasOwn` would be
> wrong there).

# Second pass — 2026-09-01 (correctness / edge-case, deeper lens)

A second sweep of the six substantive packages (gql, gremlin, core, native, sync,
serialization) with a correctness/edge-case lens, told to skip everything above and
find NEW issues. Most findings are CONFIRMED (agent traced input→wrong output, several

Almost all the highs are TS-vs-Rust byte-identity breaks the differential fuzzers miss

## Confirmed byte-identity / correctness breaks (high)

- [x] **[high][CONFIRMED]** sync `writelog.ts:107` `since` + `host.ts:616` — a REGRESSED write-log (server restart / failover / fresh node, seq resets to 0) makes `from >= seq` treat a caught-up client as current → returns `[]` not `null` → resync never fires → **every subsequent CDC write silently dropped, unbounded**. Fix: return `[]` only when `from === seq`, `null` when `from > seq`; better, add a log generation/epoch id and resync on change. **← FIXED 2026-09-01**
- [x] **[high][CONFIRMED]** native `graph.ts:1112` — `free()` doesn't consult `state.busy` (every other op gates via `live()`). - [x] **[high][CONFIRMED]** gql `clauses.ts:1257` — `EXCEPT ALL`/`INTERSECT ALL` don't dedup in TS, but native ALWAYS dedups except/intersect (`ir.rs:442`). Fix: always `distinctRows` for except/intersect; only `union` honors `all`. **← FIXED 2026-09-01**

## Snapshot helpers (checked 2026-09-01) — WON'T CONSOLIDATE (user)

Three distinct mechanisms, not one duplicated helper: native `store.ts` `snapshotOf`
(version + epoch-sum fingerprint, reference-cached rows over a RustGraph), react
`snapshotGate.ts` `nextSnapshot` (epoch-sum fingerprint + `isEqual` over a core Graph;
`useGraphSelector` delegates to it), and sync `client.ts` `getSnapshot` (push-driven,
not fingerprint-based). The only literal overlap is the one-line epoch-sum reduce, and
extracting it would add a `@lenke/native`→`@lenke/core` edge for a trivial helper.
Justified parallelism for two graph backends + one unrelated push snapshot — leave it.
